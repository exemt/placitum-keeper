# Установка

[English](INSTALL.md) · Русский

Keeper нужен там, где есть активные наборы: автоблокировки по адресу, списки, ключи лимитов. Без него
инспекторы проверяют по последнему известному составу, но внести новую запись некому. Обычно его
ставит `placitum-core`.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | запросы на запись приходят по шине, дельты уходят туда же |
| Внутренний Redis | да | состав, пакеты и снапшоты наборов |
| PostgreSQL контроллера | да | записи: значения, сроки, причины, поиск по ним из панели |

**Копия ровно одна.** Keeper — секвенсор: порядок записей определяет он, и вторая копия означала
бы две правды. Масштабируется он конвейером внутри (`WAF_KEEPER_PIPELINE`), а не репликами.

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `WAF_NATS_URL` | `NATS_URL`, затем `nats://nats:4222` | шина |
| `WAF_KEEPER_REDIS_URL` | `REDIS_INTERNAL_URL` | внутренний Redis: состояние и пакеты; обязателен, состоянию не место в буфере |
| `WAF_KEEPER_DATABASE_URL` | `postgres://waf:waf@postgres:5432/waf` | база контроллера; задавайте явно |
| `WAF_KEEPER_HTTP` | `:8094` | `/healthz` и состояние наборов |
| `WAF_KEEPER_NAME` | `keeper` | имя в кадре присутствия |
| `WAF_KEEPER_LOG` | `info` | уровень журнала |
| `WAF_KEEPER_QUEUE_MAX` | `50000` | сколько запросов ждут места в очереди |
| `WAF_KEEPER_BATCH_MAX` | `10000` | потолок пачки записей |
| `WAF_KEEPER_PIPELINE` | `4` | сколько писателей работают параллельно |
| `WAF_KEEPER_COALESCE` | `10ms` | окно, в которое события склеиваются в один пакет |
| `WAF_KEEPER_TICK` | `2s` | тик набора: живость и сверка хеша у зеркал |
| `WAF_KEEPER_SWEEP` | `1s` | уборка истёкших записей |
| `WAF_KEEPER_PULSE` | `5s` | период кадра присутствия |
| `WAF_KEEPER_SNAPSHOT_TTL` | `30s` | срок жизни снапшота в Redis |
| `WAF_KEEPER_DIFF_TTL` | `90s` | срок жизни пакета в Redis; не меньше двух сроков снапшота |

Умолчания рассчитаны примерно на десяток тысяч записей в секунду.

## Docker Compose

```yaml
services:
  keeper:
    image: placitum/keeper
    environment:
      WAF_NATS_URL: nats://nats:4222
      REDIS_INTERNAL_URL: redis://redis-internal:6379
      WAF_KEEPER_DATABASE_URL: postgres://waf:пароль@postgres:5432/waf
      WAF_KEEPER_LOG: info
      GOMEMLIMIT: 1536MiB
    mem_limit: 2g
    cpus: "4.0"
    depends_on: [nats, postgres, redis-internal]
```

`:8094` наружу не публикуют: состояние наборов панель смотрит через контроллер.

## Проверка

```sh
curl -fsS http://127.0.0.1:8094/healthz
curl -fsS http://127.0.0.1:8094/sets
```

При здоровом старте в журнале: подключение к шине, к базе и к внутреннему Redis, затем загрузка
активных наборов с числом записей. Первый запрос на запись должен получить ответ с номером в
последовательности; если ответа нет, смотрите очередь и потолки.

## Типичные ошибки

- **Реквизиты в умолчании.** `postgres://waf:waf@postgres:5432/waf` совпадает с установкой из
  core. Задавайте `WAF_KEEPER_DATABASE_URL` явно, иначе процесс может молча пойти не в ту базу.
- **Состояние — во внутреннем Redis, не в буфере.** Перепутанные адреса дают набор, который
  есть, но выглядит пустым: пакеты пишутся в один экземпляр, читаются из другого.
- **Перегрузка видна ответом.** При переполнении очереди keeper отвечает ошибкой, а не копит:
  отправитель обязан это залогировать, а не считать запись сделанной.
